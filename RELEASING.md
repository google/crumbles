# Releasing Crumbles

This document describes how to cut an official Crumbles release so that:

1. Gradle dependency and plugin artifacts are verified against committed
   SHA-256 metadata before building.
2. Users, helpline operators, and partner organizations have a published
   **signing certificate SHA-256 fingerprint** in every GitHub release note to
   compare against both a downloaded APK and the in-app footer described in
   **[HOW_TO.md](HOW_TO.md#verifying-a-provisioning-qr-code-before-you-scan-it)**.

---

## 1. Update and Commit Gradle Dependency Verification Metadata

Before cutting a release tag (and whenever dependencies or plugins change in
`build.gradle.kts` or `settings.gradle.kts`), regenerate Gradle's dependency
verification metadata on a machine with network access:

```bash
./gradlew --write-verification-metadata sha256 help
```

This creates or updates `gradle/verification-metadata.xml` with `<sha256>`
checksums for every resolved dependency and Gradle plugin.

1. Review the diff in `gradle/verification-metadata.xml` to ensure that every
   new or changed checksum corresponds to an expected dependency update.
2. Commit `gradle/verification-metadata.xml` at the release tag before building
   release artifacts.
3. With `gradle/verification-metadata.xml` present in the repository, subsequent
   `./gradlew` builds verify all resolved artifacts and fail on any SHA-256
   mismatch.

---

## 2. Build and Sign the Release APK

From the clean release tag:

1. Build the release APK with Gradle (`./gradlew assembleRelease`) and sign it
   with the official Crumbles release signing key to produce `CrumblesApp.apk`.
2. Generate the APK file checksum alongside the binary (consumed by
   `setup_device.sh`, `setup_device.command`, and `setup_device.bat`):

```bash
sha256sum CrumblesApp.apk > CrumblesApp.apk.sha256
```

> **Note:** `CrumblesApp.apk.sha256` is the SHA-256 digest of the **APK file**
> and changes with every build. It is not the signing certificate fingerprint.

---

## 3. Verify the APK Signature and Extract the Certificate SHA-256

Verify the signed APK and print the signing certificate's SHA-256 fingerprint:

```bash
./tools/print_signing_cert_sha256.sh CrumblesApp.apk
```

The script runs `apksigner verify --print-certs CrumblesApp.apk` and formats the
`Signer #1 certificate SHA-256 digest` line as 32 colon-separated uppercase
hexadecimal octets:

```text
AA:BB:CC:DD:...:FF
```

You can also run `apksigner` directly:

```bash
apksigner verify --print-certs CrumblesApp.apk
```

Notice the three formats used across Crumbles for the same certificate digest:

* **Colon-separated uppercase hex (`AA:BB:CC:...`, 32 octets)**: printed by
  `./tools/print_signing_cert_sha256.sh` and displayed at the bottom of the
  Crumbles main screen (`App signing certificate (SHA-256):` from
  `R.string.app_signing_fingerprint`).
* **Unseparated lowercase hex (64 hex chars)**: printed directly by
  `apksigner verify --print-certs` on the
  `Signer #1 certificate SHA-256 digest:` line.
* **URL-safe Base64 (`PROVISIONING_DEVICE_ADMIN_SIGNATURE_CHECKSUM`)**: embedded
  in the Android Enterprise provisioning QR code JSON payload generated by:

```bash
./tools/generate_qr_payload.sh CrumblesApp.apk \
  "https://github.com/google/crumbles/releases/download/<tag>/CrumblesApp.apk"
```

As long as the official release signing key does not rotate, the signing
certificate SHA-256 fingerprint remains identical across releases.

---

## 4. Publish the GitHub Release

Attach `CrumblesApp.apk` and `CrumblesApp.apk.sha256` to the GitHub release and
include the following verification block in **every GitHub release note**:

```markdown
### Verification Metadata

* **Signing certificate SHA-256 fingerprint** (matches the in-app footer
  `App signing certificate (SHA-256):` and
  `./tools/print_signing_cert_sha256.sh CrumblesApp.apk`):
  `<AA:BB:CC:...:FF>`
* **Signing certificate SHA-256 (`apksigner verify --print-certs` hex)**:
  `<64-char-lowercase-hex>`
* **Provisioning QR `PROVISIONING_DEVICE_ADMIN_SIGNATURE_CHECKSUM`**
  (URL-safe Base64):
  `<url-safe-base64-checksum>`
* **APK file SHA-256 (`CrumblesApp.apk.sha256`)**:
  `<64-char-apk-file-sha256>`
```

Publishing the signing certificate SHA-256 in every release note ensures that
users following **[Verify your download](README.md#verify-your-download)** or
**[Verifying a provisioning QR code before you scan it][verify-qr]** have a
published reference value to check both before installation and at any later
time inside the app.
